# 1.8 寸空气检测仪：接线、刷写和使用

适用硬件：微雪 **ESP32-S3-Touch-AMOLED-1.8 初版 / V1**，368×448 屏幕、16 MB Flash、8 MB PSRAM；SCD41 CO₂ 模块与 SFA40 甲醛模块。**V2 不适用。**

当前源码以所选 Git commit 为准，功能与构建入口见[板型说明](../main/boards/custom/waveshare-air-monitor-1.8-v1/README.md)。本仓库不提供个人设备的 Flash 备份或含凭据的已有固件。车内测量、关机电源轨、装壳温升及完整音频并发需要各自实机验收。

## 一、接四根线，两模块共用一组接口

以下焊点名称按微雪初版官方原理图确认。**认 TP 编号和模块丝印，不按照片的左右顺序判断。**

| 微雪初版焊点 | 信号 | SCD41 转接板 | SFA40 转接板 |
| --- | --- | --- | --- |
| **TP4** | 受电源芯片管理的 3.3 V，VCC3V3 | VCC | VCC |
| **TP3** | GND | GND | GND |
| **TP7** | SCL，ESP32 GPIO14 | SCL | SCL |
| **TP8** | SDA，ESP32 GPIO15 | SDA | SDA |

```text
微雪 V1                 SCD41                SFA40
TP4 / 3.3V ─────┬────── VCC
                └────────────────────────── VCC
TP3 / GND ──────┬────── GND
                └────────────────────────── GND
TP7 / SCL ──────┬────── SCL
                └────────────────────────── SCL
TP8 / SDA ──────┬────── SDA
                └────────────────────────── SDA
```

两个传感器的 I²C 地址不同：SCD41 是 `0x62`，SFA40 是 `0x5D`。主控先指定地址，再读对应设备，数据不会同时挤进来。这组线也与板上触摸、电源和音频控制器共用，固件复用同一个总线。

不同转接板的排针顺序可能不同，翻面后左右方向也会变化；请逐个核对实物 VCC / GND / SCL / SDA 丝印，不按照片或商品外形猜测。卖家写的“通常 3.3V/5V”不能确定转接板内部电路，须确认购买的这两个模块均支持 **3.3 V 供电、3.3 V I²C 电平**。有些转接板带稳压或电平转换，裸芯片参数不能直接代替整块模块参数。

板上已有约 2.2 kΩ 的 I²C 上拉。先使用已有上拉，检查传感器转接板是否也带上拉；不要把多个上拉电阻盲目叠加。线保持短，按装入后盖的长度布置，避免借长 I²C 线跨到扶手箱。需要将传感器放远时应另行设计通信链路。

**TP2 是 VBUS，不能当作 TP4 的 3.3 V 使用。** 车内从合格的 USB 5 V 电源给板子供电，车载 12 V 不接这些焊点。默认固件关闭未知电池的充电功能，第一轮调试使用 USB 供电。

建议焊接顺序：

1. 拔掉 USB，断开电池；先把传感器留在壳外。
2. 根据官方图定位 TP3 / TP4 / TP7 / TP8，完成四线连接及线束固定。焊接时避开传感器膜面，不让助焊剂、清洗剂和碎屑落到膜上。
3. 用万用表确认无 3.3 V 对地短路，SDA / SCL 未接反、未接到 5 V。
4. 先上电观察供电与读数，再装后盖。SCD41 测量有瞬时电流需求，传感器反复掉线时也要检查供电和焊点。

TP4 所在的 3.3 V 电源轨在 PMIC 真正关机后应关闭；**熄屏时传感器仍工作**。软件已经请求 PMIC 关机，是否在 USB 供电下完全断开传感器电源、持续按键是否再唤醒，仍需在板上测量确认。

## 二、先备份现有小智固件

不要先擦除 Flash。备份文件包含原固件、Wi-Fi 等配置，应自行妥善保存，不要公开上传。

命令使用 esptool **5.6.0**。可在 Python 虚拟环境安装，也可使用已准备的 ESP-IDF Python 环境：

```sh
python3 -m venv air-flash-tools
source air-flash-tools/bin/activate
python -m pip install esptool==5.6.0
```

把下列端口改成系统识别到的 ESP32 端口；macOS 通常为 `/dev/cu.usbmodem...`，Windows 为 `COM...`，Linux 通常为 `/dev/ttyACM...`。不要选择蓝牙串口。若未识别，用数据 USB 线连接，按住 BOOT 后重新接入 USB，再松开 BOOT，进入 ESP32-S3 下载模式。

```sh
AIR_PORT=/dev/cu.usbmodemXXXX
AIR_BACKUP=original-xiaozhi-16mb.bin
python -m esptool --chip esp32s3 --port "$AIR_PORT" flash-id
python -m esptool --chip esp32s3 --port "$AIR_PORT" read-flash 0x0 0x1000000 "$AIR_BACKUP"
python -c 'import hashlib,pathlib,sys; p=pathlib.Path(sys.argv[1]); assert p.stat().st_size == 16777216; print(hashlib.sha256(p.read_bytes()).hexdigest(), p.name)' "$AIR_BACKUP"
```

`flash-id` 应与 16 MB 硬件一致；保存备份文件和打印出的校验值。读取失败先处理连接问题。若工具报告加密或安全启动限制，不添加 `--force` 跳过检查。

如已安装 ESP-IDF，可从备份提取旧分区表供比较。下列方法以旧分区表位于常见地址 `0x8000` 为前提；无法解析时不据此假定兼容：

```sh
dd if="$AIR_BACKUP" of=original-partition-table.bin bs=1 skip=32768 count=4096
python "$IDF_PATH/components/partition_table/gen_esp32part.py" original-partition-table.bin original-partitions.csv
```

## 三、安装固件

本仓库不保存刷写二进制。先按第六节完成源码构建，再进入仓库的 **`build/` 目录**；该目录内有本次构建生成的 `flash_args`、`flasher_args.json` 和对应镜像。不要混用不同构建的应用、资源和分区文件。

安装前记录同一次构建输出的 SHA-256；不要拿旧固件包的校验表验证新构建。下文“包内”指同次构建的完整输出目录。

第一次刷写先只接 USB 数据线，不接电池及外加传感器；完成上面的全片备份后安装。先验证启动、触摸、短按亮灭屏、BOOT 回主页及长按关机，再断电接入传感器。没有传感器时应显示未连接，不能假造读数。

### 从现有小智切换到空气仪

推荐使用包内 `flash_args` 分段写入，它与 `flasher_args.json` 来自同一次构建：

```sh
python -m esptool --chip esp32s3 --port "$AIR_PORT" write-flash @flash_args
```

这会写入引导程序、分区表、OTA 选择信息、应用和资源。**不带擦全片参数，但不能保证原 Wi-Fi、激活和设置可直接迁移**：旧固件的分区位置、NVS 内容可能不同。先比较旧分区并保留完整备份。固件不会为修复 NVS 初始化错误自动擦除配置；如果存储不可用，它继续离线检测，界面提示设置只能暂存。

当前设计采用 16 MB 分区：

| 内容 | 地址 | 大小或说明 |
| --- | --- | --- |
| NVS | `0x9000` | `0x4000`，分段刷写清单不主动写这一项 |
| OTA 选择信息 | `0xD000` | 初始化 OTA 启动选择 |
| `ota_0` 应用 | `0x20000` | `0x3F0000` |
| `ota_1` 应用 | `0x410000` | `0x3F0000` |
| 语音等资源 | `0x800000` | 8 MiB 分区 |

**实际写入地址始终以最终包内 `flasher_args.json` / `flash_args` 为准。** 表格用于理解和核对，不作为跨版本通用地址。

包内还提供 `merged-binary.bin`。它是从 `0x0` 开始的合并镜像，包含中间填充区，写入时会影响该范围内原有配置；适合已经备份、接受重新配网和激活的完整安装。需要时使用：

```sh
python -m esptool --chip esp32s3 --port "$AIR_PORT" write-flash --flash-mode dio --flash-freq 80m --flash-size 16MB 0x0 merged-binary.bin
```

### 后续只更新应用

`xiaozhi.bin` 只是应用，不包含所需资源、分区表和启动选择。仅当两次固件的分区布局、资源和配置兼容，且已确认写入哪个 OTA 分区及启动选择时，才可单独更新应用。设备当前可能从 `ota_1` 启动，不能每次只写 `0x20000` 就认为更新成功。初次迁移请使用上面的完整分段安装。

本板型关闭小智在线固件安装和在线语音资源替换；保留已经随包安装的语音资源。今后升级使用本板型专用构建包，避免下载资源与关机同时写 Flash。启动时会验证应用镜像，但首次安装不保证另一个 OTA 槽已有可回退的有效应用。

### 恢复原来的小智

需要回退时，使用本板刷写前保存的完整 16 MB 备份，先核对当时保存的 SHA256，再进入下载模式写回：

```sh
python -m esptool --chip esp32s3 --port "$AIR_PORT" write-flash 0x0 "$AIR_BACKUP"
```

这会用备份时的内容覆盖当前整片 Flash，包括新固件和此后保存的配置。备份须来自同一块板，不能用别人的备份代替。

## 四、界面和按键

| 操作 | 行为 |
| --- | --- |
| BOOT 短按后松开 | 亮屏并回到读数主页 |
| PWR 短按后松开 | 亮屏 / 熄屏，检测继续 |
| PWR 持续按住约 3 秒 | 请求关机，停止检测和音频后请求电源芯片断电 |
| PWR 持续约 6 秒 | 电源芯片的硬件关机后备；实际行为仍需实物验收 |
| 主页面左右滑动 | 切换读数、30 分钟历史、设置 |
| 底部齿轮 / 返回图标 | 设置与主页间切换 |
| 设置 → 传感器与连接 | 查看传感器状态、数据更新时间、自动校准状态和联网信息 |

正常关机会等待采样及音频任务退出，并保存当前设置。若主任务、总线或网络操作阻塞，等待约 1.2 秒后进入断电后备流程，最后一次设置可能来不及保存；独立硬件长按后备仍保留。

上电时已按住的按键需先释放，再重新按下。BOOT 回主页会同时取消未确认的操作弹窗。BOOT 的应用内操作不进入配网、音频测试或清配置；**复位瞬间按住 BOOT 会进入芯片下载模式**，这是 GPIO0 的硬件行为。

设置页可调亮度、日间 / 夜间 / 自动主题、“减少动态”和小智语音。自动主题的位置、校时与离线条件见[行为说明](自动主题与提醒.md)。日夜亮度分别保存；正常存储可用时保留这些偏好。设置页中间的滑杆和开关优先响应自身操作，页面横滑可从屏幕边缘开始。没有自动熄屏或按键连击清除设置的操作。

历史按 5 秒一格，显示最近 30 分钟，每个时间格保留最后一个有效且处于规格内的样本。预热、掉线和缺失处断线，不补零；历史保存在 RAM，关机后重新记录。

### 首次配网及保留的小智功能

空气检测不依赖 Wi-Fi。无网络或联网超时仍显示检测页面，不自动跳到配网。

1. 打开 **设置 → 传感器与连接 → 重新配网**，在屏幕确认；确认弹窗 30 秒后过期。
2. 手机连接详情中显示的配网热点，在详情显示的地址完成配置。热点名称和地址以屏幕为准。
3. 若小智要求激活，详情显示激活码和 `xiaozhi.me`，按服务端当前流程绑定。网络服务不可用时检测仍继续。
4. 连接及激活正常后，可点击底部麦克风或使用保留的唤醒功能；可询问当前 CO₂、甲醛和温湿度。语音只读取已有快照，不另外阻塞传感器采样。

不使用语音时，在设置关闭“小智语音”，停止唤醒、采集和远程语音播放；本地开机、错误等提示音仍保留。离线不提供联网问答。配网中可从详情选择“退出配网”。语音发起重新配网仍需屏幕确认。

## 五、如何看读数

- CO₂ 单位为 **ppm**，SCD41 约每 5 秒更新；超过 15 秒没有新的有效值会标记过期。
- 甲醛单位为 **ppb**，SFA40 约每秒读取；超过 5 秒没有新的有效值会标记过期。卖家文字中的“原始数值 100 = 100 ppb”与原厂协议不符，本固件按 **100 × 0.1 = 10 ppb** 换算。
- 温度、湿度统一显示 **SCD41** 的值，不把两个芯片的温湿度取平均。
- “预热中”表示还没有可显示的测量；“稳定中”表示已有参考读数但尚未达到规格。SFA40 以自身状态位判断，不能只等固定几秒就认定稳定。读数是否有效、数据是否过期及环境是否超出额定条件分别判断。
- 程序读取并显示 SCD41 的自动校准 ASC 状态，**不会擅自执行 400 ppm 强制校准，也不改写现有 ASC 设置**。长期车内使用的校准策略需要结合实际换气和室外参照安排。

读数异常时先看“传感器与连接”，检查哪个模块未连接、是否仍预热、最近更新时间和供电。传感器要接触车内空气，不能密封进扶手箱。不要对膜面吹气、喷酒精、擦洗或用胶封住。装壳前后做对照，排查 ESP32 自热、打印材料及胶水释放对测量的影响。

SFA40 的规定工作环境是 0–50°C、10–90% RH 且不冷凝；停车暴晒可能超出这一范围。外壳材料耐热不能扩大传感器工作范围。AMOLED 日间亮度已可调，阳光直射可读性仍需在实际安装位置观察。

## 六、从源码复现构建

在本仓库根目录执行以下命令；这里的源码已经包含本项目空气仪修改。只重新下载小智上游基线不会得到空气仪功能。

固定基线与依赖：

| 项目 | 本次使用 |
| --- | --- |
| 小智上游基线 | `7e69845d818553ac045efbcde746b22bef6eecf6`，本仓库另含本项目空气仪修改 |
| ESP-IDF | `9a97f6c54ec638111ce55cd36581b3c192f15207`，`release/v6.1` |
| 目标 | `esp32s3`，板型 `waveshare-air-monitor-1.8-v1` |
| Python | 实际使用 3.12.14；ESP-IDF 工具及环境以其锁定安装为准 |
| 字体构建 | FontTools 4.56.0、lv_font_conv 1.5.3；Node / npm |
| 第三方组件 | 使用随源 `dependencies.lock`，不混用其他版本的解析结果 |

在源码目录之外准备固定 SDK，避免把 SDK 混进源码交付包：

```sh
git clone --branch release/v6.1 https://github.com/espressif/esp-idf.git ../esp-idf
git -C ../esp-idf checkout 9a97f6c54ec638111ce55cd36581b3c192f15207
git -C ../esp-idf submodule update --init --recursive
bash ../esp-idf/install.sh esp32s3
source ../esp-idf/export.sh
bash scripts/build_air_monitor.sh
```

以上 shell 示例适用于 macOS / Linux；Windows 可在支持的 ESP-IDF 环境使用相应命令。先准备可用的 Python、Git、CMake、Ninja、Node 与 npm。首次构建会按锁文件下载依赖，需联网；不要手改 `managed_components/`、`sdkconfig` 或 `build/` 来“修”配置。

`build_air_monitor.sh` 在源码的 `.air-font-tools/` 中安装锁定的字体工具，再调用项目构建入口。字体原始文件、SHA256 和许可证在新板 `assets/` 中，生成文件进入 `build/generated/air_fonts/`。构建成功后，应用为 `build/xiaozhi.bin`，合并镜像为 `build/merged-binary.bin`，刷写地址看 `build/flasher_args.json`。

本板构建还会生成 Wi-Fi 事件桥接副本，放在 `build/generated/air_wifi/`，避免配网事件与界面互相等锁。生成器先校验锁定的上游源码 SHA256，不手改依赖目录；依赖版本变化导致校验失败时，必须重新审查，不能去掉校验继续构建。

已准备字体工具时可使用原入口：

```sh
export AIR_FONT_PYTHON=/absolute/path/to/font-venv/bin/python
export AIR_FONT_CONVERTER=/absolute/path/to/node_modules/lv_font_conv/lv_font_conv.js
python scripts/build.py custom/waveshare-air-monitor-1.8-v1 --name waveshare-air-monitor-1.8-v1 --language zh-CN
```

协议、按键、存储恢复、网络恢复和原生 LVGL 界面测试方法见[源码板型 README](../main/boards/custom/waveshare-air-monitor-1.8-v1/README.md)。硬件测量尚未完成的项目以最终验证记录为准。
